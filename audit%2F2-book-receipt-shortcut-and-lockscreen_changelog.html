⑤ 修复胶片票根(film)无活动文档时回退为书籍封面屏保

GitHub issue：KO3（Kindle PaperWhite 3）+ KOReader 2026.07.2-60，用户反馈胶片票根锁屏样式显示为书籍封面；墨痕(inkstain)与菜单(menu)两种样式正常。

根因定位：

Screensaver.show 渲染路径（源码行 4427–4432）中：is_stat_based 仅对 inkstain/menu 为 true；film 被判定为非 stat_based 后，在 4429 行触发活动文档闸门——若睡眠时无打开的书籍（ui.document == nil，典型场景：从主屏/文件管理器锁屏），则调用 showFallbackScreensaver 回退到 KOReader 默认的书籍封面屏保。inkstain/menu 因跳过此闸门而永远正常。

修改内容（源码行 4429–4434，新增 6 行）：

-   local style = getLockscreenEffectiveStyle()
-   local is_stat_based = style == K.STYLE_INKSTAIN or style == K.STYLE_MENU
-   if not is_stat_based and not hasActiveDocument(ui) then
-       showFallbackScreensaver(self, orig_screensaver_show)
-       return
-   end
+   local style = getLockscreenEffectiveStyle()
+   local is_stat_based = style == K.STYLE_INKSTAIN or style == K.STYLE_MENU
+   -- 胶片票根(film)必须存在活动文档；若无则降级为墨痕(inkstain)渲染，
+   -- 避免回退到书籍封面屏保导致样式突变。
+   if style == K.STYLE_FILM and not hasActiveDocument(ui) then
+       style = K.STYLE_INKSTAIN
+       is_stat_based = true
+   end
+   if not is_stat_based and not hasActiveDocument(ui) then
+       showFallbackScreensaver(self, orig_screensaver_show)
+       return
+   end

动机（为什么改）

依据 crash.log 行 62 实证：[BookReceipt] 诗词解析完成：共%d条 200。

根因：KOReader 的 logger（frontend/logger.lua）在输出时对每个参数调用 tostring() 后 table.concat(line, " ") 拼接， 不做 printf 风格格式化。原代码把 "…共%d条" 当作格式串、把 #list 当作独立参数传入， 于是 %d 被原样输出，数量 200 沦为尾随 token。

修复方式：用 string.format() 在传入 logger 前完成格式化，日志将正确显示「共200条」。 这同样是代码库既有约定（其余 logger 调用均为纯拼接，格式化须显式处理）。
